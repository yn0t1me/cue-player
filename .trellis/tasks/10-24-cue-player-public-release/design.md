# 更名与公开发布设计

## 名称边界

展示名 Cue Player；代码元数据 cue-player-frontend / cue-player-backend；Markdown 下载前缀 cue-player-。复用现有字符串位置，不引入品牌配置框架。锁文件只更新根项目名称，核对所有第三方依赖版本和完整性值无变化。同步相关测试的文件名断言。

当前规范和 README/第三方声明正文更新名称；原有 MIT 和第三方许可文本不改。历史归档、整理日志和既有 commit 内容保持原状；新任务可说明原名以解释历史。保留目录名、数据库、data 路径和运行服务配置。

## 发布方式

通过现有 gh 登录账户创建公开仓库 yn0t1me/cue-player。原 context-english 私有仓库是历史档案，本任务不编辑其可见性或内容。本地无 origin，检查仍为空后添加新仓库地址；若执行时发现外部变化则核对，不覆盖未知远程。

更名完成并验证后，按 Trellis 提交流程准备可审阅的文件清单。工作提交后将任务分支快进到 main，创建公开仓库并推送；核对发布结果后归档任务、记录日志，再追加推送这些整理记录，最后确认远程 main 与本地一致。用户已授权公开创建与推送，无需再次询问发布权限；Git 提交遵守项目的一次性具体清单确认规则。

只推 main，不推历史私有分支、tag 或 --mirror。创建仓库不添加 GitHub 自动 README/license/gitignore，避免独立初始提交；保留本地已审阅的五个提交和新增更名记录。

## 公开检查与恢复

枚举待发布 main 的全部提交、路径和 blob，扫描真实凭证形态、私钥、运行数据和异常大文件；检查当前公开任务和日志，不输出匹配的秘密值。gitignore 本身不证明历史安全。测试占位符或上游工具中的示例必须核对语义，不做简单命中即删除。

创建前失败时保留本地更名和验证产物并说明阻塞。仓库已创建但 push 失败时保留该仓库供重试，不擅自删除或将旧仓库改为公开。发现实际凭证时先处理，不在公网试推检验；不在本任务未经范围确认重写已有历史。
