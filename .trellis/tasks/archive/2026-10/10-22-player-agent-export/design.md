# 产品收敛设计

## 状态与依据

方案已获用户明确批准，应用实施、完整检查和本机迁移已完成；具体证据与未验范围见 validation.md。产品行为以本任务 prd.md 的 R1–R13 为本次变更依据，未修改的边界继续遵循现有 spec。保留 React/FastAPI/SQLite、本地串行导入调度器和外部字幕加工，不新增依赖或云模型调用。

## 播放页与收藏

- 沿用当前播放器和相邻工作区，只保留“字幕 / 收藏”两个标签。播放器不因标签切换重新挂载，保留播放状态与面板滚动位置。
- 字幕页提供完整学习稿的复制与 Markdown 下载；收藏页提供表达与原字幕上下文的复制与 Markdown 下载。保留既有单项输出能力，批量输出限于当前视频的收藏。
- 选字菜单仅提供收藏、关闭及必要的保存状态；保留现有新建收藏撤销、重复选区复用、错误重试、键盘与焦点行为，删除笔记和问答编辑器及其草稿流程。
- 收藏始终提供所属字幕条目原文，移除上下文是否导出的复杂开关。取消收藏不会影响字幕。
- 旧版本收藏保留其锚点，界面可沿用旧版本标识和分组，不能把旧锚点画到当前字幕。导出按视频时间排序，版本只作稳定排序的内部辅助，不写入材料。
- 单视频、多链接、播放列表、合集、导入批次和失败重试保持原产品流程；学习字幕全屏、回听和跟随保持现有契约。

## 学习材料导出

### 数据来源与格式

前端使用已有查询数据生成材料，无需新的导出写接口。复制文本和 UTF-8 Markdown 文件共享材料模型，格式渲染分开，沿用安全文件名、转义和下载 URL 清理。

完整字幕从当前 Transcript.segments 按 sequence_index 输出；标题出现一次，英文每条原文完整保留。中文和词块各自可选，与播放器当前显示开关独立；初始选项仅英文。可用时提供对应选择，没有材料就不显示该选项，也不显示缺失说明。逐条缺失的可选内容直接省略，不写占位文本。

词块使用当前修订匹配并覆盖字幕条目的 ChunkLayout，按既有 Unicode 边界重建展示文本，以分隔符呈现。词块只是附加展示，不能改变原文或锚点；不为缺失词块猜测边界。查询尚未完成不能当作确定缺失，沿用正常加载/失败重试；查询错误与没有加工内容是不同状态。

收藏材料包含标题，以及逐条的“表达”和“原句”（所在字幕条目原文）。不同位置的同词表达不合并，重复的同一选区沿用现有去重策略；不附带中文、词块、备注、问题、答案、前后字幕或整篇字幕。不引入对字幕完整性的修复。

两种材料均不包含时间戳、修订信息、内部标识、来源证据、提示词和练习要求。保留视频标题，其他视频元数据不扩张为新导出字段。复制/下载不创建、删除或修改收藏；没有收藏时显示正常空态并禁止空材料输出。剪贴板或下载失败显示可重试错误。

### 发布与导出一致性

新字幕发布后刷新 transcript、chunk-layout 和 marks；不能把旧词块用于新学习稿。用户操作生成材料时从同一次已确认的修订快照取值。若正在刷新且无法确认匹配，保留正常等待/错误状态，不拼接新旧内容。旧收藏通过其原 segment_text 输出，无需重新查找当前字幕或关联问答。

## 后端与存储收敛

- 保留 GET/POST/DELETE /api/videos/{video_id}/marks。POST 仅接受选区，响应不再带 note。删除 PATCH /marks/{mark_id} 备注接口，以及所有 /questions 路由、Schema、服务与模型。
- 保留严格字段校验、Unicode code-point 偏移、当前修订创建检查、SQLite 写锁、同一选区幂等复用及历史收藏删除规则。
- 保留 transcript_mark_keys，服务于收藏去重；移除候选收藏按 note 优先级排序的逻辑，改为稳定的创建时间和 ID 排序。删除首次答案自动收藏的所有运行时代码。
- 新增 014 之后的 Alembic 015 迁移：删除 transcript_questions 表及其中数据，删除 transcript_marks.note 列。保留视频、字幕、收藏 ID、时间、选区、绑定和所有非退役表数据。
- 不改写 001–014 的历史迁移。其旧表和 note 引用是迁移历史，不属于需要删除的运行时入口。更新当前 head 假设；现有 014 的专属迁移测试固定验证 014，新增 015 迁移测试覆盖本次行为。
- SQLite 删除列策略以真实连接和外键约束验证结果为准，优先避免重建被 mark_keys 引用的整个表；若工具限制要求重建，必须证明绑定和约束完整后采用。
- 无旧客户端兼容层；旧 note 字段提交被严格模型拒绝，退役端点走现有未找到/方法不支持行为，不保留伪成功处理。

## 清理与回退

用户已授权清除开发数据中的备注、问题和答案，未授权清除收藏等其他内容。先在隔离数据库验证新建与带数据升级，再执行本机实际数据库迁移。实际迁移前停止服务、备份一致性数据库（含 WAL 情况），不把备份、数据或日志加入 Git。没有运行数据库时记录无需清理，不创建虚假清理结果。

降级可重建退役表和空备注列，但不能恢复已删除内容；不得宣称数据删除可逆。需要恢复旧应用及旧数据时，使用迁移前一致性备份。新应用和新 schema 一起部署，服务启动仍不自动迁移。

## 文件影响与规范归属

前端主要涉及 pages/VideoPage.tsx、features/transcript 的工作区、选字控制、收藏列表和输出模块、api/videos.ts、types/video.ts、相关测试及失效 CSS。按最终职责命名，复用模块而非建立通用框架。

后端主要涉及 models、schemas、transcript_marks 服务、videos 路由、错误文案、模型导出、015 迁移及相关测试。只移除退役能力，不重做导入服务或播放器适配层。

验证后更新 README、product 的 notes-and-output / reading-experience / scope-and-acceptance / glossary、必要的 subtitle-workflow，以及 contracts 的 notes-and-anchors / data-model / http-api；工程规范仅在其描述确实失效时修改。保留旧规范中仍有效的版本、锚点、发布与播放器契约。

## 风险与证据边界

最重要的回归风险是误删收藏、外键受损、旧上下文被替换，以及新旧修订数据混用。用带数据迁移、发布后收藏读写和导出测试覆盖。jsdom 的播放器测试不能代替真实 YouTube 回听、全屏与控件验收。现有原生控件问题及字幕外部适用性限制继续保留，不宣称本次自动解决。
