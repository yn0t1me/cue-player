# 公开开发资料与历史封存

日期：2026-10-21。状态：方向已接受；公开起点尚未建立。

## 选择与理由

公开代码仓库承担唯一持续开发，并共享后续 Trellis 任务和整理后的开发日志。当前产品、技术与工程规则由公开 spec 维护，安装、开发和验证所需的材料均在公开仓库内表达。这样任务、规范和代码可以共同审阅，新会话、子代理、worktree 与贡献者取得相同的必要上下文。

原私有仓库及完整 Git 历史封存。旧资料退出日常开发依赖；仍有必要的规则、理由和验收限制整理成公开材料。旧任务保持历史地位，不转换为新的 Trellis 任务。

这个决定替代早期“任务与个人记录持续保存在独立私有资料库”的设想。项目不预设嵌套私人库、目录链接或双库同步。未来如果出现具体需要保密的资料，再按其内容确定处理方式。

## 影响与边界

任务和日志按公开内容编写，提交前审阅私人信息及附件；提案、已批准范围、实现结果和未验证限制分别标明。当前规则仅在对应 spec 维护，任务引用规范，历史提案不自动授权实施。

首次公开以筛选、验证后的状态建立干净初始提交；原仓库完整历史继续保留。公开候选审阅、第三方许可边界复核和独立副本验证尚待完成，此决定不表示已经公开或取得对现存全部材料的发布授权。

维护位置、公开记录规则与准备边界见[文档规则](../README.md)。

## 许可方向

用户选择允许他人商用、修改和闭源分发，保留版权与许可声明。项目原创部分据此采用 [MIT](../../LICENSE)；随库第三方材料保留各自授权，范围与来源见[第三方声明](../../THIRD_PARTY_NOTICES.md)。这个选择不改变历史资料封存或首次公开的验证要求。
